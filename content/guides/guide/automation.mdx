For a first working route, connect the hay supply to its destination, confirm power where needed, then send material through before adding another branch. **Demo V8 added snapping at the <EntityLink kind="machines" id="hay-sell-stand">Hay Sell Stand</EntityLink>, F for No Snap mode and an E interaction at power poles to shut down the grid.** Those details are useful when a line looks connected but will not run.

## Connect the sale end first

![A conveyor runs from beside the hay pile toward the stall marked SELL HAY.](/images/find-the-needle/screenshot-1.webp)

The destination in this official screenshot is the **SELL HAY** stall. The V8 update added belt snapping there and reworked conveyor placement with automatic pathfinding.

1. Identify the selling point and leave room to approach it.
2. Place the final belt section using the sell stand's snap connection.
3. Connect upstream toward the supply or machine output you want to carry.
4. Feed a small batch and follow it all the way to the sale point. Check that the money display changes.

If placement keeps snapping where you do not want it, **F activates No Snap mode**, according to the V8 notes. Use the in-game mode indicator and prompts when switching placement behavior. Free placement is useful for layout control; it does not prove that two endpoints actually connect, so test material flow afterward.

## When powered machines stop together

Before replacing machines, check the shared electricity supply. V8 lets you **shut down the entire power grid by pressing E at a power pole**. If several machines stopped after you interacted with a pole, inspect the grid state first and follow the pole's current prompt to restore it.

The same update added a visual notice when power is below the required level. A belt delivering hay to a machine does not establish that the machine has enough power. Read the electricity indication before changing your material route.

## Find the first point where hay stops

| What you observe | Check next |
| --- | --- |
| The input belt is empty | Follow the route back to the collector or preceding machine. |
| Hay arrives but the next machine stays idle | Check electricity, the required input and the machine's output path. |
| A queue builds in front of a scanner | Watch whether the scanner processes material more slowly than it arrives. |
| Material reaches a junction but misses its destination | Trace each outgoing branch separately, including any route to the sell stand. |

These checks help isolate a fault; they are not promises that every stalled machine has the same cause. On the **<EntityLink kind="machines" id="pellet-disc-machine">Pellet Disc Machine</EntityLink>**, V8 added **BRICKS / HAY** resource indicators, so inspect those instead of assuming a visually full belt supplies everything it needs.

## Expand without bypassing the needle check

V8 introduced **<EntityLink kind="machines" id="u-splitter">U-Splitters</EntityLink>** and **<EntityLink kind="machines" id="u-joiner">U-Joiners</EntityLink>**. Players discussing scanner congestion have also suggested splitting into separate scanner lanes and joining the output afterward. That is a community layout suggestion, not a measured throughput guarantee. Test each lane before copying it across the factory.

If the goal is to check every product for needles, trace **every** path to the sale point through your scanning setup. A tidy main line does not help if another branch bypasses it. See [needles and scanners](/guides/guide/needles-and-scanners) for the developer's explanation of needles inside hay products.

Before rebuilding a stopped route, work through the [line check](/tools/line-check) to check supply, power, output and scanner coverage in order.
